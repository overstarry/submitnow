## Google 支持 IndexNow 吗？先给结论

不支持——Google 未加入 IndexNow，也没有任何单一推送协议能同时覆盖全部主流搜索引擎。最稳妥的是**双轨架构**：用 **IndexNow**（可通过免费开源的 [submitnow](/)、GitHub Actions 或本地 CLI/MCP 零成本执行，无需购买 $9–$59/月商业监控 SaaS）覆盖 **Bing、Yandex、Seznam.cz、Naver、Yep 以及 Microsoft Copilot 与 ChatGPT Search**；针对 **Google** 则维护带准确 `lastmod` 的规范 **XML Sitemap** 提交至 Google Search Console。

## 为什么不要滥用 Google Indexing API？

市面上不少所谓“Google 秒收工具”会把普通博客或电商商品页硬推给 Google Indexing API。Google 官方文档早已明确指出该接口仅面向包含 `JobPosting` 或 `BroadcastEvent` 结构化数据的页面，超范围提交通常会被静默忽略甚至降低抓取优先级。

## 如何用 submitnow 搭建双轨索引架构？

### 轨道一：Bing、Yandex 与 AI 搜索实时推送（submitnow + IndexNow）

1. 在站点根目录托管 `https://你的主机/<key>.txt`，并用 [submitnow 密钥校验器](/tools/indexnow-key-checker) 做一次公网体检。
2. 每次发布或内容更新后，只提取**新增、修改或已删除**的增量 URL（借助 [submitnow Sitemap 对比工具](/tools/sitemap-diff) 或在线 `lastmod` 时间窗口）。
3. 通过 [submitnow 批量提交工作台](/)、[GitHub Actions](/docs/integrations/github-actions) 或 [submitnow CLI / MCP Server](/docs/integrations/cli-and-mcp) 推送至 `https://api.indexnow.org/indexnow`。

### 轨道二：面向 Google 的高质量 Sitemap 发现

1. 保证 XML Sitemap 中只有最终规范的 HTTP 200 页面（剔除 `301` 跳转、`404` 和 `noindex` 页面）。
2. **仅在主体内容真实改动时更新 `<lastmod>`**——如果构建工具每次发版把全站时间都改写为当天，Google 会直接忽略你的 `lastmod`。
3. 在 `robots.txt` 中声明 `Sitemap:` 并在 Google Search Console 完成一次注册。
4. 保持首页、分类页与最新文章列表对新页面的清晰内链，提升自然发现速度。
